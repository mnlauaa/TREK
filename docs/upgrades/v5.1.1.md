# TREK v5.1.1 upgrade

## Inputs and scope

This upgrade starts from refreshed `origin/dev` at `020a51a00968052f1bf1de16c9533b8727a8edcd` on `codex/upgrade-trek-v5.1.1`. Official v5.1.1 is pinned to `95d62b7a02f3209d927504f5d21b3efe5065d2bc`; previous official v5.1.0 is `dc36c21c08f681fd2806764fad8e17b270f6f175`. On 2026-11-09, after the provenance explanation and security review, the user directed us to defer those concerns and proceed with the 5.1.1 upgrade. This records acceptance for the fixed commit, not cryptographic verification.

The dirty active checkout remains separate. No production rollout or branch promotion is part of this implementation. The release workflow deploys from `release`, so promotion remains separately gated.

## Deferred security findings

The user requested proceeding without addressing the pre-integration security findings. Two medium native-app findings remain: Watch cookie forwarding ignores host-only/Secure scope, and configured native widgets retain trip snapshots after logout. A reproduced encoded-reference/storage prefilter mismatch remains a conditional server integrity concern; end-to-end security impact is unproven. Production dependency audit found two underlying moderate/low advisories already present in v5.1.0; no application exploit path established. These are deferred, not fixed or declared harmless.

## Verification

Implementation and verification are in progress. Reproducible local logs are in `.upgrade-work/v511-evidence` in the original repository. Baseline and candidate results are recorded separately.

## Rollout gates

A fresh production-backup restore with real encryption material, storage and installed plugins remains required before production. Local tests use disposable data with `TREK_SERVICES=off`. Production writes require maintenance, a complete backup and an explicit rollback image. Rollback restores old image and pre-upgrade data together. No live production evidence is claimed.
