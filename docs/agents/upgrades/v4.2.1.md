## Database contract and rehearsal

The historical bridge endpoint remains 200. A verified legacy fork 199–202 is normalized only to that endpoint; the unchanged official migration bodies then execute 201–205. The four existing named fork migration IDs remain unchanged. Startup and the read-only audit share artifact-based classification, distinguishing official and legacy 201/202, supporting partial upgrades, and rejecting mixed or unknown lineages.

`npm run audit:v4-upgrade --workspace=server -- --db <copy>` is a preflight. Add `--require-current` after migration to require schema 205, completed fork migrations and clean integrity/foreign-key checks.

The available local database was copied with SQLite's backup API and classified as legacy fork 202. Its isolated copy converged to official 205 with all four fork IDs, no missing artifacts, `integrity_check=ok`, and zero foreign-key failures. Comparing the original columns of 117 existing tables found changes only in `addons` (the expected Naver classification) and `schema_version`. A second migration was byte-identical. The source database was not migrated.

This is a local-data rehearsal, not a confirmed fresh production-backup rehearsal. Production encryption/configuration, uploads and live plugin compatibility remain rollout gates unless separately verified.

## Delivery boundary

Deliver a tested PR targeting `dev`. Do not merge it, promote release/main, publish SDK/release tags, or deploy. A fresh complete production backup, private restore rehearsal, write-stop plan and old-image-plus-complete-backup rollback remain mandatory before a production-connected merge/deployment.

At rollout, follow the official release's PWA guidance: the already-installed older client can perform its old cache cleanup once during this first update, so launch online, wait for its reload and re-download offline map tiles if needed; do not uninstall the PWA to force the update. The new worker-update path preserves the registration and future caches. Previously settled trips with payer-less expenses may show corrected balances; recorded payments are preserved and are not automatically rewritten.
